# Genesis-linked execution and bounded forward synchronization

This increment adds an experimental `private-execution-v2` runtime contract against official go-quai v0.57.0 (`33db82f2891b267ba898ca38bd2dd8bf75cbb072`). It starts from the declared empty genesis and has no checkpoint/state import constructor. Its datadir fingerprint differs from the existing `private-hierarchy-v1` profile. Both use the same native admission, execution, branch storage, catalog, fork-choice and recovery implementation. The existing default contract and frozen-view RPC boundary remain unchanged.

Hierarchy preparation now holds its reviewed chain contract and binds each prepared permit to that contract. Permits cannot cross profiles even when their three heads match. Execution checks the parameters carried by that preparation. The new runtime dispatches to activated components only after the actual zone transaction threshold, before the economic-controller boundary, and for the covered transaction/ETX domains. Uncovered domains fail closed. This is a route toward complete consensus, not a global validating-node qualification.

The completed offline Go oracle contains 8192 consecutive native blocks from the exact genesis, including all zone/region/prime witnesses, PCRC, confirmed inbounds, receipts and state commitments. It invokes actual proof/order, AppendHeader, ValidateBody, StateProcessor.Process and ValidateState. No synthetic height checkpoint, initial allocation, fake proof, altered protocol constant or supplied historical slice is used. Rust imports each block through the canonical path and compares all selected roots. Fresh replay has 106523 checks and eight writer reopens. Known-history replay adds 16407 checks and one reopen, for 122930 checks total. These are pre-transaction blocks; no activated transaction execution is credited to this corpus.

The final node change releases the catalog view used for ancestor discovery before importing windows. This avoids retaining a discovery-only old catalog generation for the entire download. Its unrelated consensus checker rebuilt to the exact same executable hash, with unchanged oracle, input, profile, original driver and all dependency inputs. The replay evidence is therefore reused with an explicit lineage record; the changed node receives fresh independent-process qualification.

Forward acquisition uses pinned local native receipts to find a common ancestor, then Quai's existing numbered-block messages and hash-addressed higher-context witnesses. It retains at most 128 raw bundles and 32 MiB of responses per window, with a separate deadline for each window. It reserves room for a complete maximum-size next block before fetching it. Native admission checks every parent, height, work proof, context binding, transaction/state transition and commitment; native fork choice decides selection. A remote lower-score head can be admitted without replacing a better local head. A changed peer index, wrong target, invalid block or cancellation cannot manufacture a receipt or state image.

The wire fixtures use actual pinned Go request/response encoders for zero, ordinary and multi-byte heights, present hashes and typed absence. Additional tests route a valid-work Go-rejected block through an adversarial peer: only the six valid predecessors publish, they survive reopen, and valid data resumes the branch. Independent processes also test multiple windows, wrong head/height, known-head zero-I/O behavior, cancellation/resume and SIGKILL prefix recovery. The larger process corpus crosses the former 4095-unknown-block acquisition limit; source-bound final results are recorded after qualification.

On the shared 96-block workload, removing the prototype's redundant per-block hash lookup reduces application requests from 248 to 152 (38.7097%). Both archived executables use the same correctness driver and Go data. The baseline is an uninstalled forward prototype, not the preceding shipped backward-sync implementation. These are logical request counts, not a latency, throughput, allocation or RSS result. Per-window payload counters likewise measure response bytes and raw bundle counts.

A separate historical build completed the height-259216 corpus and independent receiver. Its source replay validated 259216 blocks from genesis with 3370325 checks, 405025 context views and 253 writer reopens. A separate receiver imported the first 259200 blocks, reopened at that durable boundary, imported a sixteen-block signed-Quai suffix funded only by matured native rewards, and reopened at the final head with zero additional fetches. The receiver used 2026 bounded prefix windows, 405047 application requests and 573320183 response-payload bytes; these are logical counters, not a throughput or heap/RSS result. The proof belongs to older source build `3cc6807931c1f7e7aa255f97fea3602148ec351d0a4713bec8d8cf46b7ebc9e9`, not the current installed build. Other ETX kinds, later forks, expansion, general coordinator, full EVM, automatic public-head following and live RPC remain open. See [NATIVE_FOLLOWED_GENESIS_RESULTS.md](NATIVE_FOLLOWED_GENESIS_RESULTS.md).

A three-second stack sample of the active experimental receiver identifies `pow::LightCache::item`, Keccak and `LightCache::compute` as the main CPU work in the captured busy stacks. Waiting-thread samples are separate. This is a hotspot observation during qualification with the Go oracle also running, not a controlled throughput result. The raw sample is retained with the process evidence. Reusing exact verified header proofs across acquisition/admission and improving light-DAG verification are next candidates; no new speedup is credited for them.

The macOS sample reports a **152.7M physical footprint** at that observation point. It is a single process snapshot on the small-state private corpus, not tracked allocation traffic, a comparative memory gain, full-state RPC-node RSS or production qualification.

A legacy process-harness startup helper was corrected after the forward run: it now passes the explicit v1 profile instead of an undefined name. The completed forward report retains its original helper digest. An exact source comparison proves the imported `Node` and `pack` helpers and other module code are unchanged; only the unused legacy qualification function differs. The legacy suite is rerun with the correction. This scoped lineage avoids replaying unrelated process work and does not replace any legacy check.
