# Indexed native admission and canonical recovery

This report records the indexed-catalog baseline. Current sparse Qi execution and source-bound counts are documented in [lazy Qi results](NATIVE_LAZY_QI_RESULTS.md); measurements below retain their original scope.

The private canonical client now stores admission receipts, native frontiers and selected generations in a transactional indexed catalog. Reopening reads a bounded set of receipts instead of scanning every catalog file, replaying every historical score and retaining a complete entry graph. Branch ancestry and hierarchy output use the on-demand readers described in [indexed history results](NATIVE_INDEXED_HISTORY_RESULTS.md). Global full consensus and public sync remain unfinished.

Each receipt binds its block, execution version, admitted parent, height, arrival sequence and payload digest. The payload binds the reviewed policy, raw block/context witnesses, native frontier and EVM/ETX/UTXO roots. Receipt headers are content addressed; block membership and binary ancestry indexes are checked against those headers. A single immediate-durability transaction publishes the receipt, block index, arrival generation and selected catalog head. A native store-bound permit is still required to reach publication; no remote score, receipt, checkpoint or state image is accepted.

Execution staging remains a separate durable transaction before catalog publication. The database selected-version CAS follows the catalog commit. Recovery can therefore observe an old execution head with a complete new admitted catalog generation, validate their bindings and finish selecting that version. Staged-only execution versions have no catalog receipt and cannot promote themselves. Equal entropy keeps the earlier selected frontier. Invalid candidates leave the admitted generation and selected execution checkpoint unchanged.

While a worker holds the chain lock, the local status response exposes a nonblocking admission counter updated after a durable catalog commit. It does not claim a selected height: the execution-head CAS may still be completing. Independent-process crash/cancellation tests observe this counter instead of relying on catalog filenames.

A canonical view retains its tip and an immutable indexed catalog transaction. Height/root queries follow binary receipt links and return storage errors explicitly. Admitted membership queries retain a generation and perform individual lookups; peer acquisition no longer copies an all-history set of hashes. Competing admitted forks remain available while old views retain their generation. A process-local weak registry reuses the same database handle while pinned readers survive a writer reopen. A dedicated test verifies those reads and rejection of a stale generation CAS.

The total 4,096-record catalog capacity, aggregate catalog/history byte budget and zone-height restriction are removed from this path. Cache, per-record, per-acquisition and reviewed-profile limits remain. The hierarchy overlay keeps at most 64 recent blocks and rebases sooner if an existing resource bound fills; version-header and ancestry caches are bounded. A generic catalog test stores 6,001 receipts and a competing fork, queries binary ancestors and reopens it. These are synthetic storage receipts, not 6,001 admitted native blocks or public sync evidence.

The catalog checks payload/header digests on access and detects replacement of the open database pathname. Pinned reads preserve their transaction's contents. Recovery does not scrub every unused record or every physical page at startup; corruption of an unrelated record is discovered when it is accessed. This differs from the historical full-file catalog scan. The adapted canonical storage probes check selected-generation atomicity and pathname replacement; direct catalog tests separately damage a payload and verify checksum rejection. The frozen Go input, fork-choice expectations, native block execution, roots and receipt comparisons remain fixed.

This private format is canonical version 4, indexed catalog schema 1, keyed branch marker 2, branch metadata 4, hierarchy delta 1 and execution-state codec 1. Earlier private directories are preserved and refused. Use a fresh private datadir; there is no automatic migration.

The full combined default and reduced Go-denied builds each pass **224 release tests / 186 Rust sources / 22 source assets**, with zero Go/protoc attempts. Separate Rust processes pass **165 assertions**. Persisted signed Quai/Qi/incoming components retain **18,312 Go comparisons / 1,371 cases / 2,706 state roundtrips**. Frozen RPC/SDK checks remain **70/16**. Source-bound evidence is pointed to by `results/latest-indexed-catalog-work.json`. The existing canonical corpus covers 488 checks, 25 events and 24 native blocks; the generic storage tests do not enlarge that native history. Full mixed-transaction/later-fork/nonlocal/expansion admission, complete global coordinator workers, lazy World/Qi/ETX execution state, production receipt/log indexes, pruning, automatic public head following and verified live RPC remain open. `Verifier.validate_block` remains Unsupported.

## Measurement contract

Two separate frozen comparisons measure the source change. The existing sixteen-block branch workload includes execution, parent restore, staging and durable execution-head selection, with initial database/cache setup excluded. The new canonical reopen workload first imports the exact 25-event native corpus, checking Go head/selection expectations, then drops the writer and all views. It measures a fresh writer reopen on a warm filesystem and verifies the exact final head, height, score and roots afterward. Database/cache initialization is inside this second measurement; parsing, initial imports and final checks are outside it. The process retains immutable profile initialization from setup, while the reopened verifier starts fresh.

Both comparisons compile source roles in separate Cargo targets, retain source/binary/driver hashes and archives, run timed roles sequentially, and count gross requested allocations separately. The new common reopen harness is added only to a temporary copy of the unchanged qualified baseline, then compiled identically for both roles. This is a new recovery measurement baseline, separate from the unchanged branch benchmark. No Go timing, cold-disk, whole-node TPS or RSS claim is made. The catalog adds a configured 16 MiB cache beside the 64 MiB execution database cache; these are configuration bounds, not measured resident memory.

The performance ledger preserves the first ancestry implementation's measured regression and the final source comparison. Exact raw results are pointed to by `results/latest-indexed-history-performance.json` and `results/latest-canonical-reopen-performance.json` after qualification.

The qualified branch measurement is **10.796 → 11.162 ms/block**; canonical reopen is **729.096 → 21.842 ms/open**. The [performance ledger](../../PERFORMANCE_LEDGER.md) retains all allocation counters, regressions and scope limits.
